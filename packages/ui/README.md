# @pulsedesk/ui

The **PulseDesk component library and design system** — a shared internal package that every MFE and the shell host imports from. It re-exports all used MUI components, defines the MUI theme factory, manages design tokens as CSS custom properties, and exports PulseDesk-specific composed components.

## Role in the System

This package enforces a single import contract: app code must never import from `@mui/material` or `@mui/icons-material` directly. All MUI imports go through `@pulsedesk/ui`. This gives the package the ability to:
- Apply component-level overrides (React 19 compatibility patches, custom `defaultProps`) globally.
- Export additional metadata (e.g. `tableRowSx`, `SIZES`, `ORDER_STATUS_COLORS`) alongside components so apps do not duplicate style constants.
- Switch or version MUI without changing MFE code.

## Key Features

- **`createAppTheme(mode: PaletteMode)`** — the MUI theme factory. Every palette value is a `var(--pd-*)` CSS variable reference. When MUI resolves `color: 'trading.uptick'` it produces `color: var(--pd-status-up)` in the output CSS. Colour values are never hardcoded in the theme object.
- **`tokens.css`** — generated CSS file containing two `[data-theme]` blocks (`dark` and `light`). Each block defines all CSS custom properties (`--pd-bg-canvas`, `--pd-bg-surface`, `--pd-text-primary`, `--pd-accent-primary`, `--pd-status-up`, `--pd-status-down`, `--pd-status-pending`, etc.). The file is generated by `scripts/generate-tokens-css.mjs` from `brandThemeSource.js` — do not edit it by hand.
- **Design token pipeline** — `brandThemeSource.js` is the single source of truth for brand colours and spacing. Run `pnpm tokens:generate` to regenerate `tokens.css`. Run `pnpm tokens:check` in CI to verify the generated file is up to date with the source.
- **Extended MUI palette** — `theme.ts` declares TypeScript module augmentations for `palette.trading` (`uptick`, `downtick`, `pending`, `neutral`) and `palette.background` extensions, so `sx={{ color: 'trading.uptick' }}` is fully typed.
- **Component overrides** — `createTheme`'s `components` block patches:
  - `MuiTooltip`, `MuiSnackbar`, `MuiDialog` — React 19 + `react-transition-group` v4 compatibility: guards against `nodeRef.current` being null during `componentDidMount`, preventing `TypeError: Cannot read properties of null (reading 'scrollTop')`.
  - `MuiButton`, `MuiToggleButton`, `MuiTextField`, `MuiIconButton` — size standardisation via `SIZES` constants (sm: 32 px, md: 40 px, lg: 48 px). All interactive components share the same height scale so they sit flush in toolbars and form rows.
- **Atomic design structure:**
  - `atoms/` — thin re-exports of individual MUI components (`Button`, `TextField`, `Chip`, etc.)
  - `molecules/` — PulseDesk-specific composed components: `TradeSideButton`, `FilterChip`, `StatusChip`, `SearchField`, `SortableHeader`, `NavBar`, `PnlValue`, `LiveBadge`, `PulsingChip`, `BrandWordmark`, `StatCell`, `RowDetail`, `SideFilter`
  - `organisms/` — page-level compositions (added as needed)
  - `icons/` — re-exports of `@mui/icons-material` icons used across the system
- **`SIZES` constant** — three-tier size scale (sm/md/lg) shared as a TypeScript object so theme.ts and stories can reference the same values without magic numbers.
- **`tableRowSx(index)`** — helper that returns zebra-striping and hover MUI sx for a table row at a given index. Used identically in `orders-mfe`, `portfolio-mfe`, and `trading-mfe` blotter, ensuring consistent table appearance.
- **`filterChipSx(isActive)` / `tradeSideToggleSx(side)`** — sx generators for interactive chips and BUY/SELL toggles, with complete state matrices (hover, active, hover+active) documented in the source.
- **`ORDER_STATUS_COLORS`** — maps every `OrderStatus` to a MUI Chip `color` prop value. Single source of truth used by `StatusChip` and `FilterChip`.

## How the Token System Works

```
brandThemeSource.js          ← edit brand colours here
       ↓
generate-tokens-css.mjs      ← pnpm tokens:generate
       ↓
tokens.css                   ← [data-theme="dark"] { --pd-bg-canvas: #0d0e12; … }
                                [data-theme="light"] { --pd-bg-canvas: #f4f5f7; … }
       ↓
html[data-theme="dark"]      ← set by themeSlice (trader-ui) before first render
       ↓
var(--pd-bg-canvas)          ← resolves in browser to the active theme value
```

MUI's theme object contains `'var(--pd-bg-canvas)'` as the value for `palette.background.canvas`. When MUI generates CSS via `sx`, the browser sees `background: var(--pd-bg-canvas)`. Switching theme sets the `data-theme` attribute synchronously — no React rerender required for colours.

## Running / Building

This package has no dev server. It is consumed directly from source via `workspace:*` by all apps (including Storybook). There is no build step for apps — they import the TypeScript source and let Vite/tsc compile it.

The `tokens.css` file is the only artefact that needs regenerating when brand colours change:

```bash
# Regenerate tokens.css from brandThemeSource.js
pnpm tokens:generate

# Verify tokens.css is in sync (for CI)
pnpm tokens:check
```

## Adding a New Theme

1. Add a new mode entry to `brandThemeSource.js` with all required token values.
2. Run `pnpm tokens:generate` to produce the new `[data-theme="your-name"]` block in `tokens.css`.
3. Add `"your-name"` to `THEME_MODES` in `apps/trader-ui/src/store/themeSlice.ts`.
4. No component changes needed — all colour references resolve via CSS custom properties.

## Connecting to the Rest of the System

- Declared as a `peerDependency` of itself for MUI packages to avoid version conflicts.
- Imported as `workspace:*` by all five apps and by `@pulsedesk/storybook`.
- Declared as `singleton: true` in each app's Module Federation config so only one copy of `@pulsedesk/ui` exists in the browser at runtime.
- `tokens.css` is imported once in `trader-ui/src/main.tsx` via `import '@pulsedesk/ui/tokens.css'` — the CSS custom properties are then globally available to all remotes since they run in the same document.

## Dependencies

### Runtime — peerDependencies only

This package has **zero runtime dependencies** and zero devDependencies that end up in a production bundle. Every package below is declared as a `peerDependency`, meaning the consuming app (the shell or an MFE) must provide it. This is a deliberate design constraint: if `@pulsedesk/ui` declared `@mui/material` as a direct dependency, it would bundle its own copy of MUI. When the shell also bundles MUI (as a Module Federation shared singleton), there would be two MUI instances in the browser — one from the library bundle and one from the singleton registry. Two MUI instances produce duplicate style injection, conflicting theme resolution, and doubled bundle size.

| Package | Why (peer) |
|---|---|
| `@mui/material` `>=6` | The design system extends and wraps MUI. Every component exported from `@pulsedesk/ui` is a MUI component with overrides applied via `createTheme`. There is no parallel component implementation — a `Button` from this package is MUI's `Button` with PulseDesk sizing and palette. Declaring it as a peer guarantees one MUI instance in the browser regardless of how many MFEs import this package. Chose MUI over Chakra UI, Radix, and shadcn because MUI ships every component needed (DataGrid, Dialog, Tooltip, Autocomplete, Slider, ToggleButtonGroup) with excellent TypeScript types and a mature theming API. |
| `@emotion/react` + `@emotion/styled` `>=11` | MUI v6's CSS-in-JS engine. Required as a peer for the same reason as MUI itself: two Emotion instances produce duplicate style injection and class-name collisions. Chose Emotion over styled-components because MUI v6 uses Emotion internally; mixing engines creates two separate runtime instances even when both are used in the same component tree. |
| `@mui/icons-material` `>=6` | Icon set used throughout the component library (trade arrows, status icons, sort indicators, navigation icons). Declared as a peer so consumers control the version and the icon sprite is not bundled twice. |
| `react` + `react-dom` `>=18` | Required by all JSX exports. Declared as peers so the library never ships its own React copy — a second React instance would break hook calls in every component exported from this package. |

### Dev dependencies (build tooling only, never shipped)

| Package | Why |
|---|---|
| `vite` | Build tool used to compile the library to `dist/` for Node.js backend services that consume pre-compiled CJS. Frontend apps import from `src/` directly via the `workspace:*` resolution — Vite compiles the TypeScript source inline. |
| `@vitejs/plugin-react` | Vite plugin for JSX transform during library builds and local development. |
| `typescript` | TypeScript compiler. The library ships type declarations alongside compiled output for Node.js consumers. Frontend apps get types directly from `src/`. |
| `react` + `react-dom` (dev) | Installed as devDependencies in addition to peerDependencies so the package can be developed and type-checked without requiring a consumer app to be present. Does not affect the production bundle. |
| `@types/react` | TypeScript declarations for React. Needed to type-check JSX in the library source without a consumer app providing them. |
